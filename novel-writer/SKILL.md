# Novel Writer - 小说写作技能

这是一个专业的小说写作技能，提供完整的创作流程、质量控制机制和自动化执行协议。

---

## 🎯 核心特性

1. **双层审核制** - 单章验收 + 故事段批量审核，确保质量
2. **自动化执行** - 明确的执行协议，无需用户干预
3. **进度追踪** - 实时更新 PROGRESS.md，随时掌握创作状态
4. **质量控制** - 评分系统 + 自动修改规则，保证作品水准
5. **结构化管理** - 大纲、人物、章节、审核历史完整记录

---

## 📋 工作流程

### 阶段1：项目初始化

当用户提出小说创作需求时：

1. **了解需求**
   - 询问故事类型、主题、大致情节
   - 确认目标章节数（推荐15-30章）
   - 了解特殊要求（风格、受众等）

2. **创建项目结构**
   ```bash
   mkdir -p <project-name>/{chapters,scripts}
   ```

3. **生成核心文件**（使用 references/templates.md 中的模板）
   - `RULES.md` - 执行协议
   - `PROGRESS.md` - 进度追踪
   - `outline.md` - 故事大纲
   - `characters.md` - 人物设定
   - `timeline.md` - 时间线（可选）

4. **确认故事段划分**
   - 将章节分成4-6个故事段（每段3-5章）
   - 每个故事段应有明确的叙事目标

### 阶段2：创作执行

**自动化执行协议（必须严格遵守）：**

#### 单章创作流程
```
1. 读取 PROGRESS.md 确认当前进度
2. 根据 outline.md 写作当前章节
3. 保存章节到 chapters/chapter-XX.md
4. 更新 PROGRESS.md（状态、字数）
5. 调用审稿人审核（使用 scripts/review.py）
6. 等待审核结果：
   - 评分 ≥8分 → 通过
   - 评分 <8分 → 立即修改（不问用户）
7. 修改后重新提交审核
8. 通过后检查故事段状态
```

#### 故事段完成流程
```
1. 所有章节单独通过后
2. 调用批量审核（scripts/batch-review.py）
3. 自动修改规则：
   - 【高优先级】必须修正 → 立即改
   - 【中优先级】建议调整 → 立即改
   - 【低优先级】建议优化 → 可选
4. 修改完成后继续下一故事段
```

#### 🚫 绝对禁止的行为
- ❌ 写完章节不审核就继续
- ❌ 审核未通过还继续下一章
- ❌ 忘记更新 PROGRESS.md
- ❌ 询问用户"要不要继续"（审核通过后自动继续）

### 阶段3：质量控制

**审核标准（8分制）：**

单章审核关注点：
- 情节推进是否合理
- 人物行为是否符合设定
- 语言表达是否流畅
- 伏笔设置是否自然
- 冲突是否有张力

故事段审核关注点：
- 整体节奏是否协调
- 情节连贯性
- 伏笔呼应情况
- 人物成长弧光
- 悬念递进效果

**自动修改优先级：**
- **【高】必须修正** - 逻辑漏洞、人物崩坏、重大情节bug
- **【中】建议调整** - 节奏问题、伏笔不足、描写单薄
- **【低】建议优化** - 文字润色、细节补充

### 阶段4：项目完成

所有章节和故事段审核通过后：

1. 生成完整统计（平均评分、字数、创作周期）
2. 更新 PROGRESS.md 为"已完成"状态
3. 可选：生成审核历史总结（review-history.md）
4. 可选：导出完整作品文件

## 🛠️ 关键工具

### 1. 审稿人调用

使用 `scripts/review.py` 进行单章审核：

```python
# 示例：审核第5章
python scripts/review.py chapters/chapter-05.md --outline outline.md --characters characters.md
```

返回格式：
```json
{
  "score": 8.5,
  "strengths": ["情节紧凑", "人物对话生动"],
  "weaknesses": ["伏笔不够明显"],
  "suggestions": ["在第3段增加细节暗示"]
}
```

### 2. 批量审核

使用 `scripts/batch-review.py` 进行故事段审核：

```bash
python scripts/batch-review.py --segment 1 --chapters chapters/chapter-{01..04}.md
```

返回格式：
```json
{
  "overall_score": 8.3,
  "issues": [
    {
      "priority": "高",
      "chapter": 3,
      "issue": "与第1章伏笔矛盾",
      "suggestion": "修改第3章第2段"
    }
  ]
}
```

## 🎨 写作风格指南

### 语言风格
- **第三人称限知视角** - 可切换POV角色
- **现在时为主** - 回忆/闪回用过去时
- **对话简洁有力** - 避免说教式长篇大论
- **环境描写适度** - 服务情节，不拖沓

### 节奏控制
- **前25%** - 世界观、人物、冲突引入
- **25%-50%** - 矛盾升级、悬念铺设
- **50%-75%** - 高潮前夕、真相揭露
- **75%-100%** - 终局对决、情感收束

### 章节结构
- **开头** - 吸引读者（冲突/悬念/反转）
- **中段** - 推进情节（行动/对话/揭秘）
- **结尾** - 钩子（悬念/伏笔/转折）

## ⚠️ 常见陷阱

1. **跳过审核** - 永远不要未经审核就继续，这是最大的错误
2. **过度问询** - 审核通过后立即继续，不要问"要继续吗"
3. **忽视PROGRESS.md** - 每次都必须更新，这是唯一真相来源
4. **人物OOC** - 频繁回看 characters.md，保持人物一致性
5. **伏笔遗忘** - 在 outline.md 中标记所有伏笔，定期检查回收情况

## 🔧 故障排查

### 问题1：审核一直不通过
**原因：** 可能是大纲设定有问题
**解决：** 回到 outline.md，检查情节是否合理，必要时调整大纲

### 问题2：故事段审核发现大量问题
**原因：** 单章审核标准太松
**解决：** 提高单章审核标准，必要时回溯修改前面章节

### 问题3：进度追踪混乱
**原因：** 忘记更新 PROGRESS.md
**解决：** 每次完成操作后立即更新，养成习惯

---

## 💡 最佳实践

1. **先大纲后写作** - 没有扎实的大纲，后期会很痛苦
2. **人物先行** - 人物设定越详细，写作越顺畅
3. **小步快跑** - 单章审核通过立即继续，保持创作节奏
4. **定期回顾** - 每个故事段完成后，回顾全局逻辑
5. **保存草稿** - 重大修改前备份章节文件
